# M1 shared contract

Source of truth: `docs/prd/02-message-protocol-store-and-bus.md` and the debate declarations in section 08. All types are available from the `squad_protocol` root; modules also expose their owned declarations.

| Module | Contract |
| --- | --- |
| `identities` | Distinct UUIDv7 EventId, MessageId, WorkId, ContestId, CaseId, PlanId and StepId; UUIDv4 CellId; DebateId aliases ContestId; Actor, Recipient, Target, ContextId and nonempty Text |
| `config` | Nick remains the sole nick type; MemberNick aliases it |
| `cursor` | Positive signed SQLite integers serialized as decimal strings; Cursor and HistoryPosition compare numerically |
| `envelopes` | All 36 M1 payload kinds, producer and committed envelopes, quotes, standalone cases, operational/accounting payloads |
| `debate` | State/status, setup, all 29 transitions, preflights/estimates, adjudication bundle, round scores and verdict value types |
| `verdict` | Schema-first provider round/verdict validators, exact debater coverage, rubric arithmetic, winner/override checks and committed total checks |
| `contest` | Seven ContestKind names, generic selection, setup/state/preflight, moves, steps, assignments, artifacts and reports; debate transition normalization |
| `work` | Sole executable Work schema and M1 work kinds; executor context, frozen assignment and visible token ceiling validation |
| `requests` | Request, RequestResult, FeedItem, executor/internal operations, OpenMode and frontend AST mapping |
| `capabilities` | ExecutorKey, PromptRef, safe history/work records, grants, repairs, AgentContext, object-safe readers, renderer, submit and Bus traits |
| `constants` | Canonical execution/configuration constants; `limits` is a compatibility module alias |
| `validation` | Strict JSON Schema construction and schema-then-serde decoding |

Rust fields use snake_case; wire fields follow the PRD spelling. DebateTransition keeps snake_case discriminants and uses camelCase reference fields (`outcomeEventId`, `verdictEventId`, `scoreEventId`, `workId`). Request enum discriminants retain Rust variant names, with camelCase fields; explicitly tagged wire enums follow their PRD tags.

Use `ProducerEnvelope::from_value` / `CommittedEnvelope::from_value` at envelope boundaries. These perform schema validation before serde and structural/self-consistency semantic checks; they do not establish authority against stored debate state. `validation::decode<T>` caches one compiled validator per Rust type, dispatches tagged envelopes by kind, and does the structural two-pass check for other contracts; run the type's semantic validator afterward where applicable. Direct serde derives are available for trusted internal round trips and do not replace boundary validation. Errors expose only declared field paths (dynamic map keys are redacted) and schema keywords or a generic serde failure, never input values. `HistoryMetadata` denies unknown fields even through plain serde, and its `True` marker accepts only literal true. Flattened verdicts deliberately do not combine `flatten` with `deny_unknown_fields`.

Omitted Option fields use `skip_serializing_if`. Required nullable fields remain present with null: usage, costUsd, responseModel, terminalReason, DebateState.caseId, DebateRoundScore.scores and tallyOverrideReason. Each field declares `#[schemars(extend("x-required-nullable" = true))]`; schema generation promotes marked properties to required without relying on field names. Dynamic settings/data and nick-keyed maps retain their intended open, typed schemas while complete declared objects reject unknown fields.

`verdict::validate_judge_verdict` rejects model-produced weightedTotals and roundTally, then returns an application-assembled Verdict. `validate_committed_verdict` takes the canonical debaters and authoritative round tally; the router must supply these from stored state. `validate_round_response` accepts only model scores; `validate_round_score` validates the committed carrier against admitted debaters and total rounds. The router commit step must call `DebateVerdict::validate_against(state, authoritative_tally)` or `DebateRoundScore::validate_against(state)` with stored admitted state. These check debate/case identity, canonical debaters and applicable round limits. Ledger recomputation and result fencing belong to the transactional router. `system` may author only forfeit turns and unscored round-score events; successful turns use the speaker, and scored rounds use `judge`.

`ExecutorKey::owns` verifies target/context syntax. `Work::validate_assignment` additionally checks the frozen assignment's target, context and work identity. Concrete store readers must still enforce ownership, current execution boundary, eligibility, case-bound repair access and the current room epoch; these traits expose no caller-selected history context. Agents receive AgentContext, never Bus or SQLite. `AgentContext.executor` identifies the bound executor. `ExecutionGrant.binding` freezes the resolved model slug and canonical protocol `ReasoningEffort`; both generation identities are exposed through `grant.work`. `Work` and `WorkRecord` carry router-allocated `messageId` and optional `inReplyToMessageId`; reply execution requires the latter. `ExecutorRequest::Result.output` carries only `EnvelopePayload`, leaving the envelope ID, recipients, correlation ID and timestamp to the router. The work table persists both message identities. Judge-round attempts, contest/debate/round dependencies and visible ceilings are checked before storage.

Generic setup/state/preflight carriers reject kind debate, which must use its typed contract. Generic carriers retain structure for the six unbuilt mode names. `ContestKind::is_built()` returns true only for debate. A generic carrier is not admission authority for an unimplemented mode. M1 `ContestPicked` accepts only the built debate mode. `ContestSelectionStatus::Failed` represents insufficient answers; `Stopped` represents pick cancellation. `DebatePreflight.judgeOnly` explicitly selects the one-call judge estimate, requires judgeRequested, and otherwise the full plan call count is mandatory. No later-mode envelope/work payload variants or typed tables are compiled in M1.

The existing parser keeps its API and shared VariableName, VariableUpdate and ExportScope types. `Request::from_parsed` maps every existing parser variant, preserves the successful AST for conversational requests and retains complete atomic SetVars vectors. Continue/Accept AST actions and authoritative snapshot mapping are implemented by `Request::from_parsed_with_context`. User-message identity conversion uses `MessageId::from_event`, without a string round trip. Every compiled message-identity field uses MessageId.

The initial migration lives in `crates/squad-store/migrations/0001_initial.sql`; `schema::migrate` applies it transactionally once, under WAL/FULL/foreign_keys, using SQLite user_version 1. The 25 generic/core/debate tables include provenance, repairs and daily accounting, with no later-mode table groups. `squad_store::open` applies WAL/FULL/foreign_keys to every connection. `models::save_model` returns typed ModelError domain failures. `models::save_roster(tx, models)` atomically replaces member rows while retaining the judge, validates unique nicks and contiguous roster order, and removes stale members. A savepoint restores the old roster on write failure. Delete/reinsert is necessary because the member CHECK prohibits temporarily nulling roster_order. Configuration USD settings accept only ASCII digits with an optional dot and nonempty fraction, then apply finite/range checks. Accounting helpers convert reported amounts once and round reservations upward.

Deferred integration: real executor-bound store readers; runtime context construction; concrete Bus/router; atomic commit-group and delayed-history behavior; real-reader repair/ownership isolation and agent compile-fail tests. Those require M1.P3/P4 runtime implementations. No parser source edits were necessary for this contract.

Regression fixtures changed only for required contract changes: `tests/work.rs` adds messageId and reply inReplyToMessageId; `tests/common/mod.rs` adds judgeOnly to debate preflight and switches generic debate setup/state fixtures to grill; `tests/contests.rs` adds judgeOnly and camelCase transition references. No parser compile fixes were required. `tests/contract_regressions.rs::cached_delta_validation` measures 10,000 warmed delta decodes and enforces <100 microseconds per decode in release (run `cargo test -p squad-protocol --release cached_delta_validation -- --nocapture`).
