### Structural consequences of D35 to D38

- Milestone M4 is renamed **Desktop UI (Vue renderer)**. All "web", "browser", "responsive/mobile layout" requirements are rewritten for a resizable desktop window (minimum window size instead of mobile breakpoints).
- A new milestone **M4b Electron shell and packaging** is added after M4: main process, preload with a minimal typed IPC bridge (contextIsolation on, nodeIntegration off, sandboxed renderer), server lifecycle (D36), Redis setup screen (D37), native menus and shortcuts, window state persistence, markdown export via native save dialog, electron-builder config and CI build matrix for macOS arm64 and Linux x64 (D38).
- The OpenRouter key never reaches the renderer. It lives in the main/server process only.
- Electron security baseline: no remote content loaded, strict Content-Security-Policy, external links open in the system browser, navigation and new-window creation blocked.

| D57 | The judge scores every debate round. After each round's two turns are committed, the judge (the same case context for the whole debate, still with no room memory) scores both debaters 1 to 10 for that round with a one-line reason each. The user sees a live running scorecard. Debaters do NOT see round scores until the final verdict. The next round starts without waiting for the round score. The final verdict remains the judge's overall decision; if its winner differs from the round-tally leader it must say why. |
| D58 | Between rounds the TUI shows an ASCII-art banner (FIGlet style, like `echo ROUND 1 \| toilet`): `ROUND n`, `FINAL ROUND`, `VERDICT`. Refines D48. |
| D64 | A daily spend bar is always visible (`$spent ▰▰▱▱ $max`). The max is `SQUAD_DAILY_MAX_USD` in `.env` (default 20). Spend is the real cost OpenRouter reports per call. At the max Squad stops sending new requests until the next local day or until the max is raised. This replaces the separate room budget in D22 (the debate confirmation threshold stays). |
| D65 | `$tournament`: every named entrant (or `@all`) answers; the judge ranks all answers with scores and critiques; the lowest-ranked is eliminated; survivors are told their own result and present again; repeat until one champion remains. Entrants see only their own results. Judging is blind (anonymised, shuffled labels), so Fable stays the judge even when it competes. One elimination per round. Minimum three entrants. |
| D66 | `$grill`: the user picks one model's plan (`@leader $grill`); every other model grills the leader one at a time on a shared floor that all grill participants can see; the leader answers and updates the plan after each griller; at the end of each round the leader rebuilds the full plan; repeat for `GRILL_ROUNDS` (default 2, `SQUAD_GRILL_ROUNDS` in `.env`). Up to 3 questions per turn; grillers may pass; if all pass the grill ends early. Output is the final plan plus a question-and-answer appendix. No judge. |
| D67 | Debate, tournament and grill share one contest engine; one contest runs at a time per room. Build order: debate, then tournament, then grill. |
| D68 | Modes can start from the question: `@all $debate <question>` → everyone answers → banner `CHOOSE YOUR DEBATE BROS` → the user picks two by typing `@a @b` → the debate runs. Same for `$grill` with `CHOOSE WHO GETS GRILLED` and one pick. The direct forms (`@a @b $debate`, `@leader $grill`) remain as shortcuts. The room stays usable while a pick is pending; Esc cancels and the answers remain ordinary replies. |
| D69 | `$survey` and `$probe` are v1 modes. `$survey` maps where the room agrees claim by claim; `$probe` turns a mystery into a decision tree of checks. Both were proposed by the room's own models in a blind test run. |
| D70 | `$census` (Fable's design: lens-assigned blind gap hunt, merged ledger, everyone rates each gap, and a capture-recapture estimate of gaps still unfound) and `$crosscheck` (OpenAI's design: a coverage grid built blind to the plan, checked cell by cell including every cross-lens pair) are v1 modes. Squad's stated purpose is to produce the ultimate plan, one where everything has been thought of. |
| D71 | All seven modes are scripts over one engine's shared moves. Build order: debate, grill, census, crosscheck, tournament, survey, probe. Supersedes the order in D67. |
| D72 | Census estimate range (owner decision 2026-11-25): the Chao (1987) log-normal interval around the Chao1 unseen estimate `U`. With `f1`, `f2`, `S_obs` = confirmed gaps found (confirmed ledger gaps plus rating additions): variance is `f2·[½(f1/f2)² + (f1/f2)³ + ¼(f1/f2)⁴]` when `f2 > 0`, else `f1(f1−1)/2 + f1(2f1−1)²/4 − f1⁴/(4·Ŝ)` with `Ŝ = S_obs + U`, clamped at 0. If `U > 0`: `K = exp(1.96·√ln(1 + var/U²))`, `lo = U/K`, `hi = U·K`. If `U = 0`: `lo = hi = 0`. If `S_obs = 0`: no range, the report says `Nothing found yet.`. Shown to one decimal, stored unrounded in `estimateLow`/`estimateHigh`. Called a plausible range, never a confidence interval; the shared-blind-spots caveat stays. Quiet (`Census is quiet. Good place to stop.`) requires `hi < 2`, no new confirmed gap this pass, no missing participants and no unresolved rating evidence. |

The owner approved nine further modes after a blind brainstorm across the room's own models. [New modes](11-new-modes.md) is the binding specification; these rows record the choices made in it.

| ID | Decision |
|---|---|
| D73 | Nine modes are added, names final: `$forge`, `$forecast`, `$decide`, `$negotiate`, `$blow_it_up`, `$readback`, `$debug`, `$trace`, `$rank`. All are scripts over the shared engine's moves, one contest per room as before. Squad then has sixteen modes. Build order: one registry scaffold first, then the nine modes in parallel, then one integration pass (milestone M8). |
| D74 | Registry-first build. The scaffold lands every shared-file change (kinds, states, work kinds, parser verbs and AST, export scopes, fixtures, migrations, dispatch arms, prompt registration, typeahead) and each mode then owns only its own module files. Each mode's protocol module has an `ENABLED` switch that keeps its verb out of the parser, typeahead and `/help` until the mode is built. Artifacts of the nine modes travel in one generic `contest.artifact` carrier whose body is validated by the owning mode, so a new artifact type never edits a shared enum. The typed structs in each mode's protocol module stay the normative schema. Rust identifiers for `$debug` use the `Debugging` prefix and module `debugging`; `blow_it_up` carries explicit serde renames. |
| D75 | Attempt policy for the nine modes: member calls get 2 attempts and judge calls 3, as in the four structured modes, with one change. When a member's first attempt returned output that failed validation, the second attempt is a repair carrying the diagnostics, not a plain retry. Reserved attempts are always `2 × member calls + 3 × judge calls`. |
| D76 | The engine gains a human step, used by `$readback` and `$debug`. The contest enters `AWAITING_HUMAN`, releases participant holds, keeps the active-contest claim, and waits with no expiry, as a pending pick does. Answers come through `/answer <literal text>`, through a choice-token message such as `1b 2a` for readback, and `/continue` closes the step with what has been answered. No model answers for the human and silence applies no default. |
| D77 | Three room variables: `NEGOTIATE_ROUNDS` (default 3, 1 to 6), `READBACK_ROUNDS` (default 2, 1 to 4), `DEBUG_ROUNDS` (default 3, 1 to 6), with optional `SQUAD_<NAME>` seeds that are not in `.env.example`. `$forecast` has exactly one revision round and no variable. |
| D78 | `$forge`: each member ranks every draft but its own; Borda score is the mean of `(k − p)/(k − 1)` over the ballots containing the draft. The authors of the top two drafts write the fusions. A fusion may not exceed the word count of the longest accepted draft. A blind judge ranks the best original and the fusions without being told which is which; a fusion wins only if ranked first, otherwise the best original wins. The judge never edits the winner. Chosen over judge-assembled composites so the party that grades is never the party that wrote. `2m + 3` calls. |
| D79 | `$forecast`: the judge freezes resolution criteria, date, source and void rule before any forecast and they never change. Probabilities are integers from 1 to 99. Members revise once after seeing anonymised reasons with every number withheld. The pool is the trimmed mean of log-odds (the geometric mean of odds) with `k = ⌊n/5⌋` trimmed from each end, not extremised, because the models are not independent. Spread is one sample standard deviation of log-odds around the pool and is never called a confidence interval. A gap of 2.0 or more in log-odds with at least a third of the room on each side is reported as a split. The judge names cruxes and signposts and cannot state or change the number. Outcome scoring is later work. `2m + 2` calls. |
| D80 | `$decide`: at most four options, given or shortlisted. The rubric keeps criteria named by at least two members, caps at seven by mean weight, and renormalises. Scorers do not see the weights. A cell is the median member score; totals are weighted sums. The app computes leave-one-criterion-out leaders and the flip threshold `w* = Δ_R / (Δ_R + Δ_S)` for each criterion and rival. A margin under 0.25 on the 0 to 10 scale is too close to call. The judge writes flip conditions and dissents only and has no field in which to name a winner. `2m + 2` calls with options given, `3m + 3` when generated (the brainstorm's `3m + 2` omitted the shortlist call). |
| D81 | `$negotiate`: models play both sides in v1. `P = min(3, ⌊m/2⌋)` tables; counterpart players and negotiators are drawn at random and persisted. The judge writes a hidden brief per counterpart with reservations and a walk-away rule; negotiators never see it, and counterparts never see our fallback or limits. The human sees everything, with counterpart briefs marked hypothetical. Counterparts may walk away and a failed turn is never a concession. Output is a playbook with a BATNA and ZOPA map, concession ladder and objection table. Minimum four members. `2m − P + 2PR + 2` calls. |
| D82 | `$blow_it_up`: each attacker gives up to five vectors plus one mandatory diversity-slot finding drawn from a privately assigned lens, so variety is structural. Every vector must quote the target verbatim. In the challenge round each member rules on every vector it did not write; a vector is killed when a majority of at least two verdicts call it a false positive, and a false-positive verdict must quote the text that defeats it. The judge deduplicates, sets severity and likelihood, writes mitigations and a survived or weakened status, and cannot reinstate a killed vector. The app ranks by severity times likelihood. `2m + 1` calls. |
| D83 | `$readback`: members interpret the spec blind each round; the judge logs only divergences that change behaviour, at most ten per round, each anchored to a verbatim passage. The human picks the intended reading per entry, or writes one. The judge rewrites only the passages of resolved entries; the app verifies that open passages are untouched. The loop stops when a round's ledger is empty or after `READBACK_ROUNDS`. At most `R(m + 2)` calls. |
| D84 | `$debug`: the judge selects one test from those the members proposed, never a risky one and never its own, and the test must split at least two live hypotheses. The human runs it and answers with one of the listed outcome labels plus the pasted result. Elimination is application code: a hypothesis is eliminated only when its committed prediction names a different outcome than the one the human recorded. `other`, `unknown` and `/continue` eliminate nothing. No status is called confirmed. A patch is allowed only when exactly one hypothesis is live and it has at least one consistent result from a run test. At most `(R + 1)(m + 1) + 1` calls. |
| D85 | `$trace`: whether a quote exists in its source is decided by one deterministic matcher (NFKC, quote and dash folding, whitespace collapsing, case-sensitive, contiguous, at least 12 characters), never by a model, and a quote that fails is dropped without a repair attempt. Two members who did not write a claim check entailment and scope. A claim is supported, disputed, unsupported or unverified by a fixed rule; only supported claims enter the brief's body and every paragraph cites claim IDs. Independent sources are counted separately from agreeing models. `2m + 2` calls. |
| D86 | `$rank`: the human's text is the criterion; there is no rubric step. `Q = min(n(n − 1)/2, 3n)` pairs, built from shuffled rings so the comparison graph is connected, each judged by up to three members with at most 60 judgments per member. Aggregation is Bradley-Terry fitted by the MM update with a phantom item of strength 1 holding half a win and half a loss against every item, chosen over Copeland because the design is incomplete above seven items and Copeland rewards an easy draw. The app audits three-item majority cycles; the judge explains the top and the cycles and cannot reorder. `m + 1` calls. |
| D87 | M8 adds no MCP tool. The MCP server stays roster discovery plus the tournament workflow. `forge`, `forecast`, `decide`, `blow_it_up`, `trace` and `rank` are candidates for a later milestone; `readback` and `debug` need a human-step design for MCP first. |

| D90 | The engine gains an executor call, a third work class beside member and judge calls, used by `tune.execute`. The request is bare: the candidate prompt as the system message and the case input as the user message, or one user message when the prompt carries `{{input}}`, sent byte for byte with no Squad prompt, persona, history or redaction. 180 s, 2 plain attempts, no repair, 1,024 visible tokens. Reserved attempts become `2 × member + 2 × executor + 3 × judge` calls. This extends D75. |
| D91 | `$tune`: members build the test set blind (up to three cases and three criteria each). The judge selects four to six cases and two to four criteria and writes none; a frozen case is byte-identical to its proposal and at most two come from one member. The app, not the judge, splits train and held-out by a persisted seed. No prompt author ever receives a case, an expectation, a rubric description, an output or anything about the held-out set; the only feedback is a digest of the champion's train scores and short notes, and a note that copies six consecutive words of its case is rejected. Outputs are scored 0 to 4 per criterion by a blind judge that never sees a prompt; the original's and the champion's stored outputs are scored again in every sheet so no comparison crosses judge calls. A generation's best replaces the champion only with a gain of at least 0.05. The final pick is made on held-out scores alone, among the original, the final champion and the champion before it, and a variant wins only by beating the original there by at least 0.05. Scores, promotion and the pick are application code. |
| D92 | The `$tune` executor is the judge's model by default, called bare.
